Lit best practices

Practical rules for Lit 3 render() and related lifecycle — each with an Avoid example and a Prefer example in TypeScript.

How to read this guide

Examples use Lit 3 TypeScript decorators (@property, @state, @customElement). In plain JavaScript, declare the same options with static properties — the runtime behavior is identical. Keep render() pure: no fetches, no property writes, no browser-only APIs.

0 Prefer TypeScript decorators

In TypeScript Lit apps, use @property / @state / @customElement. Use static properties for plain JavaScript (behavior is the same). Do not mix legacy and standard decorator styles in one project.

Avoid: verbose static properties in TypeScript

Avoid

@customElement('my-counter')
export class MyCounter extends LitElement {
  static properties = {
    count: { type: Number },
  };
  declare count: number;
  constructor() {
    super();
    this.count = 0;
  }
}

Prefer

@customElement('my-counter')
export class MyCounter extends LitElement {
  @property({ type: Number }) count = 0;
}

Avoid: wrong tsconfig for legacy decorators

Avoid

// tsconfig — useDefineForClassFields defaults to true (TS 3.7+)
{
  "compilerOptions": {
    "experimentalDecorators": true
    // missing: "useDefineForClassFields": false
  }
}
// Result: class fields shadow Lit accessors; @property stops updating.

Prefer

{
  "compilerOptions": {
    "experimentalDecorators": true,
    "useDefineForClassFields": false,
    "strict": true,
    "noImplicitOverride": true
  }
}

1 Keep render() pure and fast

render() should be a pure function of reactive properties and state: same inputs, same template, no side effects, cheap enough to run on every update.

Do not set reactive properties inside render()

Avoid

render() {
  this.count = this.items.length; // schedules ANOTHER update
  return html`<p>${this.count}</p>`;
}

Prefer

render() {
  return html`<p>${this.items.length}</p>`;
}

// Or cache in willUpdate when you need a field:
willUpdate(changed: PropertyValues) {
  if (changed.has('items')) this._count = this.items.length;
}

Do not fetch or mutate DOM in render()

Avoid

render() {
  fetch(`/api/user/${this.userId}`)
    .then((r) => r.json())
    .then((u) => (this.user = u));
  return html`<p>${this.user?.name}</p>`;
}

Prefer

updated(changed: PropertyValues) {
  if (changed.has('userId')) this._load();
}
async _load() {
  const r = await fetch(`/api/user/${this.userId}`);
  this.user = await r.json();
}
render() {
  return html`<p>${this.user?.name ?? 'Loading…'}</p>`;
}

2 Derive values, don’t store them

Every stored value that can be computed from other state is a chance for the two to drift apart. Keep one source of truth.

Avoid redundant counters kept in sync by hand

Avoid

@state() items: Item[] = [];
@state() remaining = 0;

addItem(item: Item) {
  this.items = [...this.items, item];
  // oops: remaining is now stale
}

Prefer

@state() items: Item[] = [];

render() {
  const remaining = this.items.filter((i) => !i.done).length;
  return html`<p>${remaining} left</p>`;
}

Cheap derivation: getter; expensive: willUpdate cache

Avoid

@property() firstName = '';
@property() lastName = '';
@state() fullName = '';

updated(changed: PropertyValues) {
  if (changed.has('firstName') || changed.has('lastName')) {
    this.fullName = `${this.firstName} ${this.lastName}`; // extra render
  }
}

Prefer

@property() firstName = '';
@property() lastName = '';

get fullName() {
  return `${this.firstName} ${this.lastName}`;
}
render() {
  return html`<h2>${this.fullName}</h2>`;
}

3 Use willUpdate() for expensive derivations

willUpdate(changedProps) runs before render(). Changes made there do not schedule another update.

Avoid deriving in updated() (stale flash + second render)

Avoid

@property() query = '';
@state() results: string[] = [];

updated(changed: PropertyValues) {
  if (changed.has('query')) {
    this.results = search(this.query); // after render with OLD results
  }
}

Prefer

willUpdate(changed: PropertyValues) {
  if (changed.has('query')) {
    this.results = search(this.query); // same cycle, one render
  }
}

Guard with changed.has()

Avoid

willUpdate() {
  this._index = buildSearchIndex(this.documents); // every update
}

Prefer

willUpdate(changed: PropertyValues) {
  if (changed.has('documents')) {
    this._index = buildSearchIndex(this.documents);
  }
}

4 Put static styles in static styles

static styles are parsed once per class and shared. Styles in the template are re-parsed per instance.

Avoid <style> inside the template

Avoid

render() {
  return html`
    <style>.card { padding: 16px; }</style>
    <div class="card"><h2>${this.title}</h2></div>
  `;
}

Prefer

static styles = css`
  .card { padding: 16px; border-radius: 8px; }
  h2 { margin: 0 0 8px; }
`;
render() {
  return html`<div class="card"><h2>${this.title}</h2></div>`;
}

Dynamic colors via CSS variables, not css`` interpolation

Avoid

static styles = css`
  .box { background: ${this.color}; } // not an instance; invalid
`;

Prefer

static styles = css`
  .box { background: var(--box-color, #1a5c6b); }
`;
render() {
  return html`<div
    class="box"
    style=${styleMap({ '--box-color': this.color })}
  ></div>`;
}

5 Use the right binding types

Wrong binding syntax causes "[object Object]", sticky boolean attributes, or broken class lists.

Objects need property bindings

Avoid

render() {
  return html`<user-list users="${this.users}"></user-list>`;
  // child gets "[object Object],…"
}

Prefer

render() {
  return html`<user-list .users=${this.users}></user-list>`;
}

Boolean attributes need ?attr=

Avoid

render() {
  return html`<button disabled="${this.loading}">Save</button>`;
  // loading=false → disabled="false" → still disabled
}

Prefer

render() {
  return html`<button ?disabled=${this.loading}>Save</button>`;
}

classMap / styleMap instead of string concat

Avoid

render() {
  const cls = 'btn ' + (this.primary ? 'primary ' : '');
  return html`<button class=${cls}>Go</button>`;
}

Prefer

render() {
  return html`<button
    class=${classMap({ btn: true, primary: this.primary })}
  >Go</button>`;
}

6 Use directives where they help

Use the simplest correct tool. Reach for a directive when it solves a real issue (keys, optional attrs, caching).

Keyed lists: repeat() vs map()

Avoid

render() {
  return html`${this.todos.map(
    (t) => html`<li><input value=${t.text}> ${t.text}</li>`
  )}`;
  // reorder: DOM reused by INDEX — focus/text jump
}

Prefer

render() {
  return html`${repeat(
    this.todos,
    (t) => t.id,
    (t) => html`<li><input .value=${t.text}> ${t.text}</li>`
  )}`;
}

Optional attributes: ifDefined()

Avoid

render() {
  return html`<a href="${this.url}">Docs</a>`;
  // url undefined → href="undefined"
}

Prefer

render() {
  return html`<a href=${ifDefined(this.url)}>Docs</a>`;
}

7 Return nothing for empty states

nothing is Lit’s explicit “render nothing / remove this attribute”. Avoid the && trap that prints "0".

The && trap

Avoid

render() {
  return html`${this.items.length && html`<ul>…</ul>`}`;
  // length === 0 → literally prints "0"
}

Prefer

render() {
  return html`${
    this.items.length > 0 ? html`<ul>…</ul>` : nothing
  }`;
}

Omit empty attributes

Avoid

render() {
  return html`<input aria-label="${this.label ?? ''}">`;
}

Prefer

render() {
  return html`<input aria-label=${this.label ?? nothing}>`;
}

8 Don’t re-create handlers or objects unnecessarily

Lit re-renders a child when a received property changes by reference. Object/array literals in the template are new every time.

Hoist stable option objects

Avoid

render() {
  return html`<chart-view
    .options=${{ theme: 'dark', animate: false }}
  ></chart-view>`;
}

Prefer

const CHART_OPTIONS = { theme: 'dark', animate: false };

render() {
  return html`<chart-view .options=${CHART_OPTIONS}></chart-view>`;
}

Memoize filtered arrays in willUpdate

Avoid

render() {
  return html`<item-list
    .items=${this.items.filter((i) => i.visible)}
  ></item-list>`;
}

Prefer

willUpdate(changed: PropertyValues) {
  if (changed.has('items')) {
    this._visible = this.items.filter((i) => i.visible);
  }
}
render() {
  return html`<item-list .items=${this._visible}></item-list>`;
}

9 Split into small components

A 300-line render() is hard to read and reuse. Use helpers for presentation; child components for local state.

Break giant templates

Avoid

render() {
  return html`
    <header>…40 lines…</header>
    <main>…120 lines…</main>
    <footer>…30 lines…</footer>
  `;
}

Prefer

render() {
  return html`
    ${this._renderHeader()}
    <main>
      <filter-bar .filters=${this.filters}></filter-bar>
      <data-table .rows=${this._rows}></data-table>
    </main>
    ${this._renderFooter()}
  `;
}

Local UI state belongs in a child

Avoid

_renderDropdown() {
  // uses this._open, this._query on the PARENT
  // every keystroke re-renders the whole parent
}

Prefer

@customElement('my-dropdown')
export class MyDropdown extends LitElement {
  @state() private _open = false;
  @state() private _query = '';
  @property({ type: Array }) options: string[] = [];
}

10 Handle async data deliberately

Async work stays outside render(). Model idle / loading / error / success and abort stale responses. Prefer @lit/task.

Render every state explicitly

Avoid

async connectedCallback() {
  super.connectedCallback();
  this.user = await (await fetch('/api/user')).json();
}
render() {
  return html`<p>${this.user.name}</p>`; // throws while undefined
}

Prefer

@state() private _user?: User;
@state() private _error?: Error;

render() {
  if (this._error) return html`<p class="err">${this._error.message}</p>`;
  if (!this._user) return html`<p>Loading…</p>`;
  return html`<p>${this._user.name}</p>`;
}

Prefer Task for args, abort, and states

Avoid

// hand-rolled loading / error / abort in every component

Prefer

private _userTask = new Task(this, {
  task: async ([id], { signal }) => {
    const res = await fetch(`/api/user/${id}`, { signal });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json() as Promise<User>;
  },
  args: () => [this.userId] as const,
});

render() {
  return this._userTask.render({
    pending: () => html`<p>Loading…</p>`,
    complete: (u) => html`<p>${u.name}</p>`,
    error: (e) => html`<p>${(e as Error).message}</p>`,
  });
}

11 Be careful with unsafeHTML

Normal bindings escape values. unsafeHTML / unsafeSVG turn that protection off.

Never pass user content unsanitized

Avoid

render() {
  return html`<div>${unsafeHTML(this.comment.body)}</div>`;
  // XSS via <img onerror=…>
}

Prefer

render() {
  return html`<div>${this.comment.body}</div>`; // escaped
}

Sanitize if you must render HTML

Avoid

render() {
  return html`<article>${unsafeHTML(marked.parse(this.markdown))}</article>`;
}

Prefer

willUpdate(changed: PropertyValues) {
  if (changed.has('markdown')) {
    this._safe = DOMPurify.sanitize(marked.parse(this.markdown) as string);
  }
}
render() {
  return html`<article>${unsafeHTML(this._safe)}</article>`;
}

12 Mind SSR and hydration

On the server, only constructor / willUpdate / render run. First client render must match the server markup.

No browser APIs in render()

Avoid

render() {
  const wide = window.innerWidth > 800;
  const theme = localStorage.getItem('theme');
  return html`<div class=${wide ? 'wide' : 'narrow'}>…</div>`;
}

Prefer

@state() private _wide = false; // same default on server + first paint

connectedCallback() {
  super.connectedCallback();
  this._mq = window.matchMedia('(min-width: 800px)');
  this._wide = this._mq.matches;
}

render() {
  return html`<div class=${this._wide ? 'wide' : 'narrow'}>…</div>`;
}

Deterministic IDs and dates

Avoid

render() {
  return html`<span id="u-${Math.random()}">${new Date().getFullYear()}</span>`;
}

Prefer

@property() uid = '';
@property({ type: Number }) year = 0;

render() {
  return html`<span id=${`u-${this.uid}`}>${this.year}</span>`;
}

13 Use requestUpdate() sparingly

Declare reactive properties and let Lit batch updates. Manual requestUpdate() is for changes Lit cannot see.

Immutable updates instead of silent mutation

Avoid

addTodo(t: Todo) {
  this.todos.push(t); // same reference → no update
}

Prefer

addTodo(t: Todo) {
  this.todos = [...this.todos, t];
}

Don’t sprinkle requestUpdate after every assignment

Avoid

reset() {
  this.name = '';
  this.requestUpdate();
  this.age = 0;
  this.requestUpdate();
}

Prefer

@property() name = '';
@property({ type: Number }) age = 0;

reset() {
  this.name = '';
  this.age = 0; // batched into one render
}

@state for internal reactivity, not public @property

Avoid

@property() _isOpen = false; // becomes public API

Prefer

@state() private _isOpen = false;

Quick reference

Need to… Put it in…
Derive a value from changed props willUpdate() (cheap: a getter)
Read or touch DOM after render firstUpdated() / updated()
Add listeners, timers, subscriptions connectedCallback() + cleanup in disconnectedCallback()
Load data Task (@lit/task) or lifecycle + @state
Browser-only APIs (SSR) connectedCallback() / firstUpdated()
Share styles static styles (array of css``)
Pass objects/arrays to a child .prop= with a stable reference
Keyed, reorderable list repeat()
Optional attribute ifDefined() / nothing
Mutate a collection Replace it with a new one (immutable update)
