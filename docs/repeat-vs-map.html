map() vs repeat()

A Lit teaching component that shows, side by side, how list rendering keyed by index differs from list rendering keyed by identity.

The repeat-vs-map component

<repeat-vs-map> is a Lit 3 custom element that renders the same list twice: once with Array.map(), and once with Lit’s keyed repeat() directive. Each row has a label and an editable text field. The inputs are deliberately uncontrolled — their values live in the DOM — so you can feel how Lit reuses nodes when the list order changes.

Component source lives in the Lit teaching repo at src/components/repeat-vs-map.ts (github.com/schnellsoft/lit).

How to try the demo

  1. Type different text into several inputs on both panels.
  2. Press Shuffle or Reverse.
  3. Watch where the typed values stay: by list position (map) or with the item id (repeat).

map() versus repeat()

Array.map()

Lit treats the mapped templates like a list keyed by index. When items move, DOM nodes at each position are reused and updated in place. Uncontrolled input values therefore appear to “stick” to the row position, not to the logical item.

repeat() with keys

repeat(items, (item) => item.id, …) associates each template with a stable key. When the array is reordered, Lit moves the existing DOM nodes with their items — so typed values travel with Item A, Item B, and so on.

When to use which

  • map() — fine for static or append-only lists with no per-row DOM state.
  • repeat() — prefer when items reorder, insert in the middle, or hold focus, selection, or form state.

Minimal patterns

// Index-based (map)
items.map((item) => html`<li>${item.label}</li>`)

// Identity-based (repeat)
repeat(
  items,
  (item) => item.id,
  (item) => html`<li>${item.label}</li>`
)
